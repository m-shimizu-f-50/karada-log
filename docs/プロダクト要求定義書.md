# プロダクト要求定義書

## 1. プロダクトビジョンと目的

### ビジョン

「毎日の体の記録を、もっと簡単に」

毎日の体の状態を継続的に記録・可視化することで、ユーザーが健康管理やダイエットを無理なく習慣化できる環境を提供する。

### 目的

- 体重・食事・運動の記録を一元管理できる場所を提供する
- LINE連携により入力の手間を最小限にし、継続しやすくする
- データを可視化し、ユーザーが自分の変化を実感できるようにする

---

## 2. ターゲットユーザーと課題・ニーズ

### ターゲットユーザー

- ダイエットに取り組んでいる方
- 毎日の体重・食事・運動を手軽に記録したい方
- 継続的な健康管理を習慣化したい方

### ユーザーの課題

| 課題 | 詳細 |
|------|------|
| 記録が続かない | 入力の手間が多く、アプリを開くこと自体が億劫になる |
| データが分散する | 体重・食事・運動を別々のアプリで管理し、全体像が見えない |
| 効果が実感しにくい | 記録はしているが可視化されず、モチベーションが維持できない |

### ユーザーのニーズ

- 毎日ストレスなく記録できるシンプルなUI
- 普段使いのLINEから入力できる手軽さ
- 体重の推移・カロリー収支がひと目でわかるグラフ表示

---

## 3. 主要機能一覧

| 機能 | 概要 |
|------|------|
| 体重記録 | 毎日の体重入力・グラフ表示・目標体重管理 |
| 食事記録 | 食事内容の入力・カロリー自動計算・朝昼夜別管理 |
| 運動記録 | 種目・時間・消費カロリーの記録 |
| カロリー管理 | 摂取カロリー vs 消費カロリーの差分表示 |
| LINE連携 | LINEテキストで食事・運動を入力→アプリに自動反映 |
| ログイン機能 | Googleアカウントでログイン（NextAuth.js） |

### フェーズ2以降（将来機能）

| 機能 | 概要 |
|------|------|
| 食事カロリー自動計算 | 食品名を入力するだけで外部食品DBからカロリーを自動取得（`getCalories` 関数の差し替えで対応） |
| 写真による食事認識 | 食事の写真を撮影するだけでカロリーを自動認識・記録 |

---

## 4. 成功の定義

- ユーザーが継続して（7日以上連続で）記録を続けられる
- 体重・食事・運動の3つの記録がすべて1画面で確認できる
- LINEからの入力がアプリに正しく反映される
- スマホブラウザでストレスなく操作できる（レスポンシブ対応）

---

## 5. ビジネス要件

- 基本無料枠のインフラで運用可能であること
- 唯一の費用はドメイン代（任意）に抑えること
- Vercelへのデプロイで継続的なデリバリーを実現すること

---

## 6. ユーザーストーリー

### 体重管理

- ユーザーとして、毎日の体重を素早く入力したい。なぜなら、習慣として続けるために手間を最小限にしたいから。
- ユーザーとして、体重の推移をグラフで見たい。なぜなら、ダイエットの効果を視覚的に実感したいから。
- ユーザーとして、目標体重を設定したい。なぜなら、具体的なゴールに向けてモチベーションを保ちたいから。

### 食事管理

- ユーザーとして、朝昼夜ごとに食事内容を記録したい。なぜなら、食習慣を時間帯別に把握したいから。
- ユーザーとして、食事のカロリーが自動計算されてほしい。なぜなら、自分で調べる手間を省きたいから。
- ユーザーとして、LINEから食事内容を送るだけで記録されてほしい。なぜなら、アプリを開く手間すら省きたいから。

### 運動管理

- ユーザーとして、運動の種目・時間・消費カロリーを記録したい。なぜなら、日々の活動量を把握したいから。

### カロリー管理

- ユーザーとして、1日の摂取カロリーと消費カロリーの差分を確認したい。なぜなら、カロリーバランスをコントロールしてダイエットを進めたいから。

## 7. 受け入れ条件

### 体重記録

- [ ] 日付・体重（kg）を入力して保存できる
- [ ] 過去の体重推移が折れ線グラフで表示される
- [ ] 目標体重を設定・変更できる
- [ ] グラフに目標体重のラインが表示される

### 食事記録

- [ ] 朝・昼・夜・間食の区分で食事を記録できる
- [ ] 食品名・カロリーを手動入力して保存できる
- [ ] 1日の合計摂取カロリーが表示される

### 運動記録

- [ ] 運動種目・時間・消費カロリーを入力して保存できる
- [ ] 1日の合計消費カロリーが表示される

### カロリー管理

- [ ] 摂取カロリーと消費カロリーの差分（カロリー収支）が表示される

### LINE連携

- [ ] LINEからテキストメッセージを送信すると食事・運動が記録される
- [ ] 記録完了時にLINEへ確認メッセージが返信される

### ログイン

- [ ] Googleアカウントでサインイン・サインアウトができる
- [ ] ログインしていない状態ではデータにアクセスできない

## 8. 機能要件

### FR-01: ユーザー認証

- Googleアカウント（OAuth 2.0）を利用したログイン
- セッション管理はNextAuth.jsで実装
- 未認証ユーザーはログインページへリダイレクト

### FR-02: 体重記録

- 日付・体重値（小数点1桁）を登録・編集・削除できる
- 最低30日分の推移グラフを表示する
- 目標体重を1件設定できる

### FR-03: 食事記録

- 食事区分（朝・昼・夜・間食）と食品名・カロリーを登録・削除できる
- カロリーはユーザーが手動入力する（フェーズ2で外部食品DB連携による自動入力に移行予定）
- カロリー取得ロジックは独立した関数（`getCalories`）として実装し、将来の自動計算への差し替えを容易にする
- 1日単位で合計カロリーを集計する

### FR-04: 運動記録

- 運動種目・時間（分）・消費カロリーを登録・編集・削除できる
- 1日単位で合計消費カロリーを集計する

### FR-05: カロリー収支

- 摂取カロリー合計・消費カロリー合計・差分を日次で表示する

### FR-06: LINE連携

- LINE Messaging APIを利用してWebhookでメッセージを受信する
- テキスト解析によって食事・運動の記録を自動生成する

---

## 9. 非機能要件

### パフォーマンス

- 主要画面の初回表示: 3秒以内（LCP）
- データ保存操作のレスポンス: 1秒以内

### 可用性

- Vercelの無料枠SLAに準じる

### セキュリティ

- 認証されたユーザーのみ自分のデータにアクセスできること
- XSS・SQLインジェクション対策を実施すること
- 環境変数で機密情報を管理すること

### ユーザビリティ

- スマホブラウザ（iOS Safari / Android Chrome）で快適に操作できること
- レスポンシブデザインで画面幅320px以上に対応すること

### 運用コスト

- インフラは基本無料枠で運用できること（Supabase / Upstash / Vercelの無料プラン）
