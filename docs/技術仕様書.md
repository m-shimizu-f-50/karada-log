# 技術仕様書

## 1. テクノロジースタック

### フロントエンド（`frontend/`）

| レイヤー | 技術 |
|---|---|
| フレームワーク | Next.js（React） |
| 言語 | TypeScript |
| スタイリング | Tailwind CSS |
| グラフ | Recharts |
| フォーム | React Hook Form + Zod |
| 認証 | NextAuth.js（Googleログイン） |

| レイヤー | 技術 |
|---|---|
| フレームワーク | Hono（Node.js） |
| 言語 | TypeScript |
| ORM | Prisma |
| バリデーション | Zod |
| デプロイ | Render（無料枠・スリープあり） |

### インフラ

| 役割 | サービス |
|---|---|
| データベース | Supabase（PostgreSQL・無料枠500MB） |
| LINE連携（フェーズ2） | LINE Messaging API |

## 2. アーキテクチャ概要

```
[ ユーザー（ブラウザ）]
        │
        ▼
[ Vercel: Next.js フロントエンド ]
  ├── 画面描画（React）
  ├── NextAuth.js（Google OAuth）
  └── バックエンドAPI呼び出し（fetch + JWT）
        │
        │ HTTP リクエスト（Authorization: Bearer <JWT>）
        ▼
[ Render: Hono バックエンド ]
  ├── JWT 検証ミドルウェア
  ├── ルーティング（/api/weight, /api/meal, /api/exercise）
  └── Prisma 経由でDB操作
        │
        ▼
[ Supabase: PostgreSQL ]
```

### 認証フロー

```
1. フロントエンド（NextAuth.js）が Google OAuth を処理
2. ログイン成功後、NextAuth.js が JWT（セッショントークン）を発行
3. フロントエンドがバックエンドを呼ぶ際、Authorization ヘッダーに JWT を付与
4. バックエンドが JWT を検証してユーザーを特定
```

## 3. CI/CD

### 概要

GitHub Actions（CI）+ Vercel / Render（CD）を組み合わせた構成。
`main` ブランチへの直接 push を禁止し、必ず PR 経由でマージする運用とする。

```
[ 開発者 ]
    │
    │ feature/* ブランチを作成して実装
    ▼
[ GitHub: Pull Request を作成 ]
    │
    │ PRを作成すると自動起動
    ▼
[ GitHub Actions: CI ]
    ├── frontend: Lint / Type Check / Build
    └── backend:  Lint / Type Check / Build
    │
    │ 全ジョブ成功 → merge ボタンが有効になる
    ▼
[ GitHub: main ブランチへ merge ]
    │
    ├──▶ [ Vercel: フロントエンド自動デプロイ ]
    └──▶ [ Render: バックエンド自動デプロイ ]
```

---

### CI（GitHub Actions）

#### ワークフローファイル

`.github/workflows/ci.yml`

#### トリガー

`main` ブランチへの Pull Request 作成・更新時に起動。

#### ジョブ構成

| ジョブ名 | 対象 | コマンド |
|---|---|---|
| frontend-lint | frontend/ | `npm run lint` |
| frontend-type-check | frontend/ | `npm run type-check` |
| frontend-build | frontend/ | `npm run build` |
| backend-lint | backend/ | `npm run lint` |
| backend-type-check | backend/ | `npm run type-check` |
| backend-build | backend/ | `npm run build` |

#### 使用する Node.js バージョン

`20`（LTS）

---

### ブランチ戦略

```
main          ← 本番環境。直接 push は禁止。PR のみ受け付ける。
develop       ← 開発統合ブランチ
feature/*     ← 機能開発用（例: feature/add-weight-form）
fix/*         ← バグ修正用（例: fix/calorie-calculation）
```

## 4. 環境変数管理

機密情報はコードに直接書かず、環境変数で管理する。

### フロントエンド（`frontend/.env.local`）

| 変数名 | 用途 |
|---|---|
| `NEXTAUTH_URL` | NextAuth.js のベース URL |
| `AUTH_SECRET` | NextAuth.js のセッション暗号化キー |
| `AUTH_GOOGLE_ID` | Google OAuth クライアント ID |
| `AUTH_GOOGLE_SECRET` | Google OAuth クライアントシークレット |
| `NEXT_PUBLIC_API_URL` | バックエンド API の URL |

### バックエンド（`backend/.env`）

| 変数名 | 用途 |
|---|---|
| `DATABASE_URL` | Supabase PostgreSQL 接続文字列 |
| `AUTH_SECRET` | JWT 検証用シークレット（フロントエンドと同じ値） |
| `PORT` | サーバーのポート番号（デフォルト: 8080） |

## 7. 技術的制約と要件

- インフラはすべて無料枠で運用（Supabase / Vercel / Render の無料プラン）
- Render の無料枠はスリープあり（15分無操作で停止・次のリクエストで再起動）
- スマホブラウザ（iOS Safari / Android Chrome）での動作を優先
- 画面幅 320px 以上のレスポンシブデザインに対応
