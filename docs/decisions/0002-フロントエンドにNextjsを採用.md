# ADR-0002: フロントエンドフレームワークに Next.js を採用

- 日付: 2026-05-10
- 状態: 承認済み

## 背景

React ベースのフロントエンドフレームワークの選定が必要だった。
スマホブラウザでの動作を優先し、SEO は不要（ログイン必須のアプリ）。

## 検討した選択肢

| 選択肢 | 概要 |
|---|---|
| **Next.js** | React の本番フレームワーク。App Router・SSR・SSG 対応 |
| Vite + React | 軽量でシンプルな SPA。SSR なし |
| Remix | フルスタックフレームワーク。Web 標準を重視 |

## 決定

**Next.js（App Router）** を採用する。

## 理由

- 2024〜2025年の React 系フロントエンドで最も採用されているフレームワーク
- 求人市場・実務での採用率が高く、学習価値が高い
- App Router（Server Component）により、データ取得とUIの設計パターンを学べる
- NextAuth.js との親和性が高く、認証実装がシンプルになる
- Vercel（開発元）が提供する無料デプロイ環境と相性が良い

## トレードオフ・注意点

- App Router は比較的新しい概念（Server Component / Client Component の使い分け）があり、最初は混乱しやすい
- Pages Router（旧方式）の情報が混在するため、検索時に注意が必要
