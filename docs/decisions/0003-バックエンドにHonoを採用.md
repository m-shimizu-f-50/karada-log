# ADR-0003: バックエンドフレームワークに Hono を採用

- 日付: 2026-05-10
- 状態: 承認済み

## 背景

Node.js でバックエンド API サーバーを構築するにあたり、フレームワークの選定が必要だった。
TypeScript での開発を前提とし、実務で通用する技術を学ぶことを重視した。

## 検討した選択肢

| 選択肢 | 特徴 |
|---|---|
| **Express.js** | 最も普及・情報量が多い・学習リソース豊富 |
| **Hono** | モダン・TypeScript 前提・軽量・マルチランタイム対応 |
| **Fastify** | 高速・TypeScript 対応・Express より構造化されている |
| NestJS | エンタープライズ向け・opinionated・学習コスト高 |

## 決定

**Hono** を採用する。

## 理由

- 2024〜2025年にかけて急速にトレンドとなっており、新規プロジェクトでの採用が増加している
- TypeScript を前提に設計されており、型安全な API 開発ができる
- Express に近い書き味で、Express の経験が活かしやすく学習コストが低い
- マルチランタイム対応（Node.js・Cloudflare Workers・Bun など）のため、将来の移行コストが低い
- 日本発のフレームワークで日本語ドキュメントやコミュニティが充実している

## トレードオフ・注意点

- Express と比べてまだ情報量・採用事例が少ない
- 大規模プロダクションでの実績は Express・NestJS より少ない
- Node.js での実行には `@hono/node-server` が必要（Hono 本体は特定ランタイムに依存しないため）
