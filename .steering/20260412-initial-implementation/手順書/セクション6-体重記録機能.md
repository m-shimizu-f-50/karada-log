# セクション6: 体重記録機能

## このセクションで作ったもの

体重を記録・表示するための機能一式を実装しました。

```
作ったもの一覧
─────────────────────────────────────────────────────
バックエンド
  backend/src/lib/validations.ts      ← 入力値の検証ルール
  backend/src/routes/weight.ts        ← 体重APIのエンドポイント
  backend/src/index.ts                ← weightRoute を登録（追記）

フロントエンド
  frontend/src/types/weight.ts                              ← 型定義
  frontend/src/app/(authenticated)/weight/actions.ts        ← サーバーアクション
  frontend/src/components/organisms/WeightForm.tsx          ← 体重入力フォーム
  frontend/src/components/organisms/WeightGoalForm.tsx      ← 目標体重フォーム
  frontend/src/components/organisms/WeightChart.tsx         ← 折れ線グラフ
  frontend/src/components/organisms/WeightHistory.tsx       ← 記録一覧・削除
  frontend/src/app/(authenticated)/weight/page.tsx          ← ページ本体
─────────────────────────────────────────────────────
```

---

## 全体の流れ（データの動き）

```
ユーザー操作
    ↓
フロントエンド（Next.js）
    ├── 画面表示時   → page.tsx がサーバーでバックエンドAPIを呼び出す
    └── ボタン押下時 → Server Action がバックエンドAPIを呼び出す
              ↓
バックエンド（Hono）
    └── weight.ts が受け取り → Prisma → Supabase（PostgreSQL）に保存
```

## バックエンド側の実装

### 1. バリデーションスキーマ（validations.ts）

バリデーションとは「ユーザーが入力した値が正しい形式かチェックする」仕組みです。

```typescript
// backend/src/lib/validations.ts
import { z } from 'zod'

// 体重登録用のスキーマ
export const weightSchema = z.object({
  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/, '日付は YYYY-MM-DD 形式で入力してください'),
  weight: z.number().min(20).max(300),
})

// 目標体重用のスキーマ
export const weightGoalSchema = z.object({
  targetWeight: z.number().min(20).max(300),
})
```

**Zodとは？**

Zodはバリデーションライブラリです。`z.object()` でオブジェクトの形を定義し、`safeParse()` を呼ぶと正しい形かどうか判定してくれます。

```typescript
const result = weightSchema.safeParse({ date: "2026-01-01", weight: 68.5 })
result.success  // true → OK、false → エラー
result.data     // パース後のデータ（success の場合）
result.error    // エラー情報（failure の場合）
result.error.issues[0].message  // エラーメッセージ（Zod v4）
```

> **注意（Zod v4 の変更点）**
>
> 以前のバージョン（v3）では `result.error.errors[0].message` でした。  
> Zod v4 からは `result.error.issues[0].message` に変わりました。

### 2. 体重API（weight.ts）

体重に関するAPIエンドポイントを5つ定義しました。

| メソッド | パス         | 役割                 |
|---------|-------------|----------------------|
| GET     | /api/weight       | 直近30件を取得       |
| GET     | /api/weight/goal  | 目標体重を取得       |
| POST    | /api/weight       | 体重を登録（同日上書き）|
| DELETE  | /api/weight/:id   | 記録を削除           |
| PUT     | /api/weight/goal  | 目標体重を登録・更新  |

**重要なポイント: ルートの定義順**

```typescript
// ✅ 正しい順番：/goal を /:id より先に定義する
weight.get('/goal', async (c) => { ... })
weight.delete('/:id', async (c) => { ... })

// ❌ 逆にすると /goal が "id = goal" と解釈されてしまう
weight.delete('/:id', async (c) => { ... })  // ← これが先だと...
weight.get('/goal', async (c) => { ... })   // ← /goal がここに到達しない
```

**同じ日付の記録を上書きする仕組み（upsert）**

```typescript
const record = await prisma.weightRecord.upsert({
  where: { userId_date: { userId, date: dateObj } },  // この条件で探す
  create: { userId, date: dateObj, weight: weightValue }, // なければ作成
  update: { weight: weightValue },                     // あれば更新
})
```

`upsert` は「あれば更新、なければ作成」という便利な操作です。  
これができるのは、`schema.prisma` で `@@unique([userId, date])` という制約を設定したためです。

**自分の記録だけ削除できる仕組み**

```typescript
const record = await prisma.weightRecord.findUnique({ where: { id } })
if (!record) return c.json({ error: '記録が見つかりません' }, 404)
if (record.userId !== userId) return c.json({ error: 'アクセスが拒否されました' }, 403)
```

削除前に「この記録は本当にログイン中のユーザーのものか？」を確認しています。  
他人の記録を削除しようとすると 403 エラーを返します。

## フロントエンド側の実装

### 3. 型定義（weight.ts）

```typescript
// frontend/src/types/weight.ts
export type WeightRecord = {
  id: string
  date: string      // "2026-01-01" のような文字列
  weight: number    // kg
  createdAt: string
}

export type WeightGoal = {
  id?: string
  targetWeight: number | null  // 目標未設定の場合は null
  updatedAt?: string
}
```

TypeScriptでは型を定義することで「このデータがどんな形かコードで表現」できます。  
API から受け取るデータの形と一致させることで、ミスを防ぎます。

### 4. サーバーアクション（actions.ts）

Server Action とは「ボタンを押したときにサーバー側で実行される関数」のことです。

```typescript
'use server'  // ← これがあるとサーバー側で動く関数になる

import { apiFetch } from '@/lib/api-client'
import { revalidatePath } from 'next/cache'

// 体重を登録する
export async function addWeightAction(date: string, weight: number) {
  const res = await apiFetch('/api/weight', {
    method: 'POST',
    body: JSON.stringify({ date, weight }),
  })
  if (!res.ok) {
    const data = await res.json()
    throw new Error(data.error ?? '登録に失敗しました')
  }
  revalidatePath('/weight')  // ← ページのキャッシュを破棄して最新データを取得させる
}
```

**`revalidatePath` とは？**

Next.js はパフォーマンスのために一度取得したデータをキャッシュ（一時保存）します。  
体重を登録した後、`revalidatePath('/weight')` を呼ぶことで「/weight ページのキャッシュを無効化」し、次回アクセス時に最新データを取得させます。

これにより「登録したのにグラフが更新されない」という問題を防いでいます。

### 5. WeightForm（体重入力フォーム）

```typescript
'use client'  // ← ユーザー操作があるのでクライアントコンポーネントにする

import { useState, useTransition } from 'react'
```

**`useTransition` とは？**

```typescript
const [isPending, startTransition] = useTransition()

startTransition(async () => {
  await addWeightAction(date, weightNum)  // Server Action を呼ぶ
})
```

`startTransition` は「この処理は優先度が低い」と React に伝える仕組みです。  
`isPending` が `true` の間はボタンを無効化して「保存中...」と表示できます。

**バリデーション（入力値チェック）**

```typescript
const weightNum = parseFloat(weight)
if (isNaN(weightNum) || weightNum < 20 || weightNum > 300) {
  setError('体重は20〜300kgで入力してください')
  return  // ← ここで処理を止める
}
```

フロントエンドでも基本的なチェックをしています。  
バックエンドでも Zod でチェックしているため、二重にチェックされています。

### 7. WeightChart（折れ線グラフ）

Recharts というグラフライブラリを使っています。

```typescript
'use client'  // ← グラフ描画はブラウザ側で動くのでクライアントコンポーネント必須

import {
  LineChart, Line, XAxis, YAxis,
  CartesianGrid, Tooltip, ReferenceLine, ResponsiveContainer,
} from 'recharts'
```

**主なコンポーネントの役割**

| コンポーネント   | 役割                       |
|----------------|---------------------------|
| `ResponsiveContainer` | グラフを親要素の幅に合わせて伸縮させる |
| `LineChart`    | グラフ全体のコンテナ        |
| `Line`         | 折れ線を描く               |
| `XAxis`        | 横軸（日付）               |
| `YAxis`        | 縦軸（体重 kg）            |
| `CartesianGrid`| 背景のグリッド線           |
| `Tooltip`      | マウスオーバーで値を表示    |
| `ReferenceLine`| 目標体重の横線             |

**Y軸の範囲を動的に設定**

```typescript
const weights = records.map((r) => r.weight)
const minWeight = Math.min(...weights)
const maxWeight = Math.max(...weights)
const yMin = Math.floor(minWeight - 2)  // 最小値より2kg下
const yMax = Math.ceil(maxWeight + 2)   // 最大値より2kg上
```

体重の変化が小さい場合でも変化が見やすいように、データの範囲±2kgを表示します。

### 9. WeightPage（ページ本体）

ページは Server Component（サーバーコンポーネント）です。  
`async` 関数にして、サーバー側でデータを取得してから HTML を返します。

```typescript
// ← async をつけることでサーバー側で非同期処理ができる
export default async function WeightPage() {
  const { records, goal } = await fetchWeightData()
  ...
}
```

**2つのAPIを同時に呼び出す**

```typescript
const [recordsRes, goalRes] = await Promise.all([
  apiFetch('/api/weight'),
  apiFetch('/api/weight/goal'),
])
```

`Promise.all` を使うと複数のAPIリクエストを**並列**で実行できます。  
順番に実行すると「体重取得(300ms) + 目標取得(300ms) = 600ms」かかりますが、  
並列にすると「同時実行 = 300ms」で済みます。

---

## エラーハンドリングの方針

```typescript
const records: WeightRecord[] = recordsRes.ok ? await recordsRes.json() : []
const goal: WeightGoal = goalRes.ok ? await goalRes.json() : { targetWeight: null }
```

APIが失敗した場合でもページが壊れないよう、エラー時はデフォルト値（空配列・null）を使っています。

## まとめ

このセクションで学んだ重要な概念:

1. **Zodバリデーション** — リクエストの入力値を型安全に検証する
2. **upsert** — 「あれば更新、なければ作成」のDB操作
3. **Server Action** — ボタン操作でサーバー側の処理を実行する
4. **revalidatePath** — データ変更後にNext.jsのキャッシュを更新する
5. **useTransition** — 非同期処理中のローディング状態を管理する
6. **Promise.all** — 複数のAPIリクエストを並列実行してパフォーマンスを改善する
7. **サーバーコンポーネント** — ページのデータ取得はサーバー側で行う
