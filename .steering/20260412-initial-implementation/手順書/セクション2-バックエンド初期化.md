# セクション2: バックエンド初期化

## このセクションで作るもの

`http://localhost:8080/health` にアクセスすると `{"status":"ok"}` が返ってくる、
最小構成の API サーバー。

---

## 前提知識

### フロントエンドとバックエンドの違い

```
【フロントエンド】                    【バックエンド】
ブラウザで動く                        サーバーで動く
ユーザーが見る画面を作る              データの保存・取得・処理を担う
HTML / CSS / JavaScript / React       Node.js / Hono
localhost:3000                        localhost:8080
```

このプロジェクトでは両方を別々のサーバーとして動かす。
フロントエンドがバックエンドに「データをください」とリクエストを送り、
バックエンドがデータベースからデータを取得して返す。

### API とは

「Application Programming Interface」の略。
プログラム同士が会話するための窓口。

レストランに例えると：
- フロントエンド = お客さん
- API = メニューと注文口
- バックエンド = キッチン
- データベース = 食材庫

お客さん（フロントエンド）は「ハンバーガーをください」とメニュー（API）を通じて注文する。
キッチン（バックエンド）が食材庫（DB）から食材を取り出して料理して返す。

### HTTP メソッドとは

API リクエストの「動詞」。何をしたいかを表す。

| メソッド | 意味 | 例 |
|---|---|---|
| `GET` | データを取得する | 体重記録の一覧を取得する |
| `POST` | データを新規作成する | 体重を記録する |
| `PUT` | データを更新する | 目標体重を更新する |
| `DELETE` | データを削除する | 体重記録を削除する |

### Hono とは

Node.js 用の軽量な Web フレームワーク。
「どの URL に、どのメソッドでアクセスされたら、何を返すか」を簡単に定義できる。

```typescript
// GET /health にアクセスされたら { status: "ok" } を返す
app.get('/health', (c) => {
  return c.json({ status: 'ok' })
})
```

## 実施内容

### 1. `package.json` を作成した

```bash
cd backend
npm init -y  # -y で全質問にデフォルト値で答える
```

これで `backend/package.json` が作られる。

### 2. パッケージをインストールした

```bash

npm install prisma @prisma/client    # データベース操作（セクション3で使う）

# 開発時だけ必要なパッケージ
npm install -D typescript @types/node tsx
```

### 3. `tsconfig.json` を作成した

TypeScript の動作設定ファイル。手動で作成した。

### 4. `src/index.ts` を作成した

サーバーのエントリーポイント（起動ファイル）。

### 5. `.env` / `.env.example` を作成した

環境変数を管理するファイル。

## 作成されたファイルの解説

### `tsconfig.json` — TypeScript の設定

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "skipLibCheck": true,
    "esModuleInterop": true,
    "types": ["node"]
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

各設定の意味：

| 設定 | 意味 |
|---|---|
| `target: "ES2022"` | TypeScript を ES2022 の JavaScript に変換する |
| `module: "NodeNext"` | Node.js の最新モジュール形式（ESM）を使う |
| `outDir: "./dist"` | コンパイル後のファイルを `dist/` フォルダに出力する |
| `rootDir: "./src"` | TypeScript のソースファイルは `src/` にある |
| `strict: true` | 厳格な型チェックを有効にする（型エラーを厳しく検出） |
| `types: ["node"]` | Node.js の型定義を使う（`process.env` などが使えるようになる） |
| `include: ["src"]` | `src/` フォルダだけをコンパイル対象にする |
| `exclude: ["node_modules", "dist"]` | これらは除外する |

### `package.json` のスクリプト

```json
{
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js",
    "type-check": "tsc --noEmit"
  }
}
```

| スクリプト | コマンド | 説明 |
|---|---|---|
| `npm run dev` | `tsx watch src/index.ts` | 開発用。ファイルを保存するたびに自動で再起動 |
| `npm run build` | `tsc` | TypeScript → JavaScript に変換して `dist/` に出力 |
| `npm run start` | `node dist/index.js` | 本番用。変換済み JS を実行 |
| `npm run type-check` | `tsc --noEmit` | 型エラーチェックのみ（ファイル出力なし） |

**`tsx` とは？**
通常 TypeScript は `tsc` でコンパイルしてから JavaScript として実行する。
`tsx` はこの2ステップを省略して、`.ts` ファイルを直接実行できるツール。
開発中はいちいちコンパイルしなくていいので便利。

`watch` オプションをつけると、ファイルの変更を監視して自動で再起動する（ホットリロード）。

### `src/index.ts` — サーバーのエントリーポイント

```typescript
import { serve } from '@hono/node-server'
import { Hono } from 'hono'
import { cors } from 'hono/cors'

// ① Hono アプリを作成
const app = new Hono()

// ② CORS ミドルウェアを全リクエストに適用
app.use(
  '*',  // すべてのパスに適用
  cors({
    origin: process.env.FRONTEND_URL ?? 'http://localhost:3000',
    credentials: true,
  })
)

// ③ /health エンドポイントを定義
app.get('/health', (c) => {
  return c.json({ status: 'ok' })
})

// ④ サーバーを起動
const port = Number(process.env.PORT) || 8080

serve({ fetch: app.fetch, port }, () => {
  console.log(`Server running on http://localhost:${port}`)
})
```

#### ① `new Hono()` — アプリの作成

Hono のアプリインスタンスを作る。
このインスタンス（`app`）に対してルートやミドルウェアを登録していく。

#### ② CORS ミドルウェア

**CORS（Cross-Origin Resource Sharing）とは？**

ブラウザには「異なるオリジン（ドメイン）へのリクエストをブロックする」という安全機能がある。

```
フロントエンド: http://localhost:3000
バックエンド:   http://localhost:8080
           ↑ポートが違う = 別オリジン
```

ポートが違うだけでも「別オリジン」とみなされ、ブラウザがリクエストをブロックする。
バックエンド側で「`http://localhost:3000` からのリクエストは許可する」と明示することで解決する。

```typescript
cors({
  origin: process.env.FRONTEND_URL ?? 'http://localhost:3000',
  // ↑ このオリジンからのリクエストを許可する

  credentials: true,
  // ↑ クッキーや Authorization ヘッダーを含むリクエストも許可する
  //   ログイン情報（JWT）のやり取りに必要
})
```

`'*'` は「すべてのパスに適用する」というワイルドカード。

**ミドルウェアとは？**
リクエストが来てからレスポンスを返すまでの間に実行される処理のこと。
CORSチェック・認証確認・ログ記録などに使う。

```
リクエスト → [CORSミドルウェア] → [認証ミドルウェア] → ルートハンドラ → レスポンス
```

#### ③ `/health` エンドポイント

```typescript
app.get('/health', (c) => {
  return c.json({ status: 'ok' })
})
```

- `app.get(パス, 処理)` — GET メソッドのルートを定義する
- `c` — コンテキスト。リクエスト情報やレスポンスを扱うオブジェクト
- `c.json(...)` — JSON 形式でレスポンスを返す

`/health` はサーバーが正常に動いているか確認するためだけのエンドポイント。
デプロイ後の動作確認や、CI/CD での死活確認に使う。

#### ④ サーバー起動

```typescript
const port = Number(process.env.PORT) || 8080
//           ↑環境変数 PORT があればその値を使い、なければ 8080

serve({ fetch: app.fetch, port }, () => {
  console.log(`Server running on http://localhost:${port}`)
  // ↑ 起動完了時にこのログが出る
})
```

`process.env.PORT` は環境変数。
本番環境（Render など）はポート番号を環境変数で指定するため、それに対応している。

### `.env` と `.env.example`

**`.env`** — 実際の値を書くファイル（Git に含めない）

```
DATABASE_URL="postgresql://..."  # 本物の接続文字列
AUTH_SECRET=...                  # 本物の秘密鍵
PORT=8080
FRONTEND_URL=http://localhost:3000
```

**`.env.example`** — キーだけ書いたサンプルファイル（Git に含める）

```
DATABASE_URL=postgresql://user:password@localhost:5432/karada_log
AUTH_SECRET=your-auth-secret
PORT=8080
FRONTEND_URL=http://localhost:3000
```

なぜ分けるのか？
`.env` にはパスワードや秘密鍵が含まれるため、GitHub に公開すると漏洩してしまう。
そのため `.gitignore` に追加して Git 管理から除外する。
代わりに `.env.example` をコミットして「こんな環境変数が必要ですよ」とチームに伝える。

## ファイル間の関係

```
npm run dev を実行
        ↓
tsx が src/index.ts を実行
        ↓
Hono アプリが起動、ポート 8080 で待機
        ↓
ブラウザから http://localhost:8080/health にアクセス
        ↓
CORSミドルウェアが origin チェック
        ↓
app.get('/health') のハンドラが実行される
        ↓
{ "status": "ok" } が返る
```

---

## ハマった点・補足

- **フロントエンドとバックエンドで `npm run dev` を両方実行する**: 開発中は両方のサーバーを同時に起動しておく必要がある。ターミナルを2つ開いてそれぞれで実行する
- **`process.env` を使うには `@types/node` と `"types": ["node"]` が必要**: TypeScript は標準では Node.js の API（`process`・`Buffer` など）を知らない。`@types/node` をインストールし、`tsconfig.json` に `"types": ["node"]` を追加することで使えるようになる
