# 初回実装 設計書

## 実装方針

学習しながら理解を深めることを優先し、以下の原則で進める。

- **1セクション = 1学習単位**: 各セクションを完結させてから次へ進む
- **動く → 理解する → 次へ**: 実装後に動作確認し、コードの意味を確認する
- **小さく積み上げる**: 機能を一気に作らず、画面表示 → データ取得 → 保存 → 削除 の順に積み上げる

---

## セクション別 実装アプローチ

---

### セクション 1: プロジェクト初期化

#### 学習ポイント

- `create-next-app` で生成されるファイル群の役割
- `app/` ディレクトリ（App Router）とページのルーティング
- `tsconfig.json` / `.eslintrc` / `tailwind.config.ts` の基本設定
- `package.json` の依存関係管理

#### 実装アプローチ

1. `create-next-app` でプロジェクト作成（TypeScript・Tailwind・App Router を選択）
2. 不要なデフォルトコードを削除してクリーンな状態にする
3. 必要なパッケージを一括インストール
4. リポジトリ構造定義書に従ってフォルダ構造を作成

#### インストールするパッケージ

```bash
# ORM
npm install prisma @prisma/client

# 認証
npm install next-auth@beta

# バリデーション
npm install zod

# フォーム
npm install react-hook-form @hookform/resolvers

# グラフ
npm install recharts

# 開発ツール
npm install -D @types/node vitest @vitejs/plugin-react
```

### セクション 2: DB設計・Prisma セットアップ

#### 学習ポイント

- Prisma スキーマ（`schema.prisma`）でのモデル定義方法
- マイグレーションとは何か（スキーマの変更をDBに反映する仕組み）
- Prisma Client の使い方（`prisma.user.findMany()` など）
- Supabase の接続文字列の取得方法

#### 実装アプローチ

1. Supabase でプロジェクトを作成し、接続文字列を取得
2. `.env.local` に `DATABASE_URL` を設定
3. `prisma/schema.prisma` に5テーブルのモデルを定義
4. `npx prisma migrate dev` でマイグレーション実行
5. `lib/db.ts` に Prisma Client のシングルトンを作成

#### Prisma スキーマ方針

- `機能設計書.md` のテーブル定義をそのまま Prisma モデルとして記述
- `@@unique([userId, date])` で1日1記録の制約を設定（WeightRecord）
- `@map` / `@@map` でカラム名・テーブル名をスネークケースにマッピング

---

### セクション 3: 認証（NextAuth.js）

#### 学習ポイント

- OAuth 2.0 の認証フロー（認可コード → アクセストークン → ユーザー情報取得）
- NextAuth.js v5（Auth.js）のセットアップ方法
- `session` オブジェクトで現在のユーザーを取得する方法
- `middleware.ts` で未認証ユーザーをリダイレクトする仕組み

#### 実装アプローチ

1. Google Cloud Console で OAuth クライアントを作成
2. `lib/auth.ts` に NextAuth.js の設定を記述（Google Provider + Prisma Adapter）
3. `app/api/auth/[...nextauth]/route.ts` にハンドラを配置
4. `middleware.ts` でログイン必須ルート（`/dashboard`, `/weight`, `/meal`, `/exercise`）を保護
5. ログインページ（`app/page.tsx`）に「Googleでログイン」ボタンを配置

---

### セクション 4: レイアウト・ナビゲーション

#### 学習ポイント

- `app/layout.tsx`（ルートレイアウト）の役割
- Server Component と Client Component の違いと使い分け
  - `onClick` などのイベントが必要 → Client Component（`"use client"`）
  - データ取得・認証確認 → Server Component
- Tailwind CSS でのダークテーマ・グラデーション実装

#### 実装アプローチ

1. `app/layout.tsx` にグローバルレイアウト・背景エフェクトを実装
2. `components/layout/Header.tsx` を作成（タイトル + ログアウトボタン）
3. `components/layout/BottomNav.tsx` を作成（アクティブなタブをグラデーションで強調）
4. `app/(authenticated)/layout.tsx` に認証済みページ共通レイアウトを作成

---

### セクション 5: 体重記録機能

#### 学習ポイント

- Server Actions とは（フォームからサーバー側の関数を直接呼び出す仕組み）
- `useOptimistic` / `useTransition` を使った UX の改善（応答速度の向上）
- Recharts の `LineChart` / `ResponsiveContainer` / `XAxis` / `YAxis` の基本的な使い方
- API Route のパターン（`app/api/weight/route.ts`）

#### 実装アプローチ

1. API Route を作成（`GET /api/weight`、`POST /api/weight`、`DELETE /api/weight/[id]`）
2. `GET /api/weight/goal`、`PUT /api/weight/goal` を追加
3. `WeightForm.tsx` を実装（日付・体重入力 → Server Action で保存）
4. `WeightChart.tsx` を実装（Recharts の `LineChart` で過去30日の推移表示）
5. `WeightHistory.tsx` を実装（記録一覧 + 削除ボタン）
6. `WeightGoalForm.tsx` を実装（目標体重の設定・変更）
7. `app/weight/page.tsx` で各コンポーネントを組み合わせる

---

### セクション 6: 食事記録機能

#### 学習ポイント

- `useState` でタブの選択状態を管理する方法
- URL の `searchParams` を使った状態管理（タブ選択をURLに反映）
- フォームの `reset` 処理（保存後に入力欄をクリアする）

#### 実装アプローチ

1. API Route を作成（`GET /api/meal`、`POST /api/meal`、`DELETE /api/meal/[id]`）
2. `MealTabBar.tsx` を実装（朝食/昼食/夕食/間食 タブ切り替え）
3. `MealForm.tsx` を実装（食品名・カロリー入力 → 保存）
4. `MealList.tsx` を実装（選択中の食事区分の記録一覧 + 削除）
5. `app/meal/page.tsx` で組み合わせ、合計摂取カロリーを表示

---

### セクション 7: 運動記録機能

#### 学習ポイント

- セクション5・6で習得したパターンの応用
- Server Component と Client Component の境界の設計

#### 実装アプローチ

1. API Route を作成（`GET /api/exercise`、`POST /api/exercise`、`DELETE /api/exercise/[id]`）
2. `ExerciseForm.tsx` を実装（種目・時間・消費カロリー入力 → 保存）
3. `ExerciseList.tsx` を実装（記録一覧 + 削除）
4. `app/exercise/page.tsx` で組み合わせ、合計消費カロリーを表示

---

### セクション 8: ダッシュボード

#### 学習ポイント

- Server Component での並行データ取得（`Promise.all` を使って複数APIを同時に呼ぶ）
- カロリー収支の計算ロジック（摂取 − 消費）
- Next.js の `revalidatePath` でキャッシュを更新する仕組み

#### 実装アプローチ

1. `WeightSummary.tsx` を実装（今日の体重 + 目標との差分を表示）
2. `CalorieSummary.tsx` を実装（摂取/消費/収支 + プログレスバー）
3. `app/dashboard/page.tsx` で並行データ取得 + 各コンポーネントを組み合わせる

---

### セクション 9: 仕上げ・品質チェック

#### 学習ポイント

- GitHub Actions の YAML 設定
- `npx tsc --noEmit` で型エラーのみ確認する方法
- スマホブラウザでの動作確認方法（ローカル IP でアクセス）

#### 実装アプローチ

1. `.github/workflows/ci.yml` を作成（Lint → 型チェック → ビルド）
2. `npm run lint` を通す
3. `npx tsc --noEmit` を通す
4. `npm run build` を通す
5. スマホブラウザでの見た目・操作を確認
